# Dependency Inventory

All direct NuGet package versions are managed in `Directory.Packages.props`. The versions below were selected as current stable releases compatible with .NET 10 when the scaffold was created.

| Package | Version | Projects | Concrete need | Why the platform alone is insufficient |
|---|---:|---|---|---|
| `Asp.Versioning.Mvc`, `Asp.Versioning.Mvc.ApiExplorer`, `Asp.Versioning.OpenApi` | 10.2.1 | `ManagerEmployee.Api` | URL-segment API versioning (`api/v{version:apiVersion}`), `api-supported-versions` reporting, and a versioned OpenAPI document with the version substituted into paths. | ASP.NET Core has no built-in API versioning model. |
| `Microsoft.AspNetCore.OpenApi` | 10.0.15 | `ManagerEmployee.Api` | Generate and serve the OpenAPI document through `AddOpenApi` and `MapOpenApi`. | ASP.NET Core supplies the hosting primitives, but the OpenAPI document services are distributed through this package. |
| `Microsoft.EntityFrameworkCore.SqlServer` | 10.0.15 | `ManagerEmployee.Infrastructure` | Provide EF Core SQL Server persistence, migrations, composite identity, and optimistic concurrency. | EF Core provider support is not part of the ASP.NET Core shared framework. |
| `Microsoft.EntityFrameworkCore.Design` | 10.0.15 | `ManagerEmployee.Api` | Enable design-time migration discovery and generation with the API as the startup project, so `dotnet ef` uses the application's configuration. It is marked `PrivateAssets=all`. | Migration tooling requires design-time services that should not flow to consumers. |
| `Microsoft.Extensions.DependencyInjection.Abstractions` | 10.0.15 | `ManagerEmployee.Application` | Lets Application expose `AddApplication()` for its own handler registrations without referencing ASP.NET Core. | Class libraries do not get the DI abstractions implicitly. |
| `Microsoft.Extensions.Http` | 10.0.15 | `ManagerEmployee.Infrastructure` | `IHttpClientFactory` typed and named clients for TrackTik. | Class libraries do not get the HTTP client factory implicitly. |
| `Microsoft.Extensions.Options.ConfigurationExtensions` | 10.0.15 | `ManagerEmployee.Infrastructure` | Bind and validate `TrackTikOptions` from the `TrackTik` configuration section. | Class libraries do not get options binding implicitly. |
| `FluentValidation` | 12.1.1 | `ManagerEmployee.Infrastructure` | Declarative provider payload validation; both provider validators compose one shared rule set and report errors under provider JSON field names. | Hand-written validators duplicated the same required/length/email/date/enum checks per provider. |
| `Microsoft.EntityFrameworkCore.InMemory` | 10.0.15 | `ManagerEmployee.Infrastructure.Tests`, `ManagerEmployee.Api.IntegrationTests` | Verify no-tracking read-store projections and composite-identity behavior without requiring a shared SQL Server during the default test run. | The SQL Server provider cannot execute portable isolated tests without an external database; migration application remains the authority for SQL Server behavior. |
| `Microsoft.AspNetCore.Mvc.Testing` | 10.0.15 | `ManagerEmployee.Api.IntegrationTests` | Host the real API with `WebApplicationFactory` for integration tests. | The shared framework does not include the test-host package. |
| `MSTest` | 4.5.2 | All four test projects | Supply the MSTest framework, adapter, analyzers, and test SDK through its meta-package. | .NET does not include a test framework or runner adapter by default. |

FluentAssertions and Moq are not included. FluentValidation is limited to provider payload validation in Infrastructure; Domain values still validate and normalize themselves through focused factories as a last line of defense. MediatR, AutoMapper, JSON-schema libraries, resilience packages, NATS clients, and Testcontainers remain intentionally excluded until concrete mandatory behavior requires them.
